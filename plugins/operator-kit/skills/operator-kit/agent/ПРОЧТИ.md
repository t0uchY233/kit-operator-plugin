# Агент «Помощник оператора по методике КИТ» — прототип

## Что это
Набор файлов, который превращает любую чат-модель в помощника операторской компании. Агент по данным проекта:
1. говорит, каких данных не хватает;
2. предлагает последовательность действий;
3. формулирует задачи исполнителям;
4. считает, какой оператор нужен компании: роли, число позиций и кто какую функцию выполняет.

Каждая рекомендация идёт со ссылкой на правило из материалов С. Н. Веселкова. Если правила нет, агент так и говорит и заносит вопрос в список для автора.

## Состав
| Файл | Назначение |
|---|---|
| `ИНСТРУКЦИЯ.md` | Системная инструкция агента: роль, четыре режима, правила поведения, формат ответа |
| `анкета_проекта.md` | Какие данные по проекту нужны на каждом этапе; раздел 6 — профиль компании для расчёта оператора |
| `знания/методика.md` | Методика оператора: этапы, роли, правила, совещания, красные линии, пробелы, вопросы автору |
| `знания/правила.md` | Все правила с идентификаторами и дословными цитатами |
| `знания/глоссарий.md` | Термины и роли, как у автора |
| `знания/функции_оператора.md` | Каталог из 60 функций оператора: кто делает по источникам, как часто, что остаётся у клиента |
| `знания/параметры_расчёта.md` | Роли, что о каждой говорит источник, способ счёта и допущение по каждой роли, функции ролей |
| `расчёт_оператора.py`, `модель_расчёта.json` | Программа расчёта и её данные. `параметры_расчёта.md` собирается из JSON |
| `примеры/` | Разобранный расчёт для условного подрядчика и его профиль |
| `проверка/` | Тесты программы и проверочные случаи для агента |

## Как запустить
- **В этой папке (Claude Code).** Написать: `/operator-kit` и дальше данные проекта или вопрос.
- **В проекте Claude или в ChatGPT.** Текст `ИНСТРУКЦИЯ.md` вставить в инструкции проекта. Анкету, файлы из `знания/` и пример из `примеры/` загрузить в знания проекта. Данные конкретного проекта присылать в чат. Программу там запускать не обязательно: агент посчитает вручную по `параметры_расчёта.md`.
- **Плагин ChatGPT desktop.** Установить «Оператор КИТ» из источника «КИТ — оператор»; в новом чате вызвать `@operator-kit` или задать вопрос. Инструкция установки лежит в `README.md` репозитория плагина.
- **Расчёт без агента.** `python3 расчёт_оператора.py --пример > мой_профиль.json`, поправить числа в этом файле, затем `python3 расчёт_оператора.py мой_профиль.json`. Профиль из `примеры/` не править: с ним сверяются тесты.

## Как устроен расчёт оператора
- На входе профиль компании: продукт оператора, число контрактов и бригад; по желанию — смены, рабочие дни, кто ставит ключевых руководителей, совмещения ролей и свои нормы.
- Роли и функции взяты из материалов автора. **Норм численности в материалах нет**, поэтому число позиций — всегда либо допущение модели, либо норма, которую дал человек. Результат — расчётный сценарий, а не норма методики.
- Способов счёта четыре: одна позиция на подрядчика; по одной на проект или бригаду; число бригад ÷ 7 ± 2; число единиц ÷ норма человека. Первые три — допущения.
- Где посчитать не из чего, стоит «неизвестно», и в итог строка не входит.
- Считаются позиции, а не люди. Расчёт делается на одного подрядчика.
- Допущения записаны в `модель_расчёта.json` у каждой роли. После правки пересобрать `знания/параметры_расчёта.md` командой `python3 расчёт_оператора.py --модель` и пример в `примеры/`; тесты в `проверка/` это проверяют.

## Что агент не умеет
- Не знает 40 статей с Дзена и большинства видео автора: в базу вошли 38 статей блога, 15 внутренних документов и конспект шести видео (это пересказ, а не дословная речь автора).
- Не считает оклады, стоимость команды и трудозатраты: таких норм в материалах нет.
- Не решает за автора противоречия источников (например, буфер 30% или 50%) — показывает оба варианта.
- Не даёт юридических заключений.
- Не считает вердикт чек-листа «72 часа»: его считает Excel-файл.

## Что взято из книги «AI-агенты изнутри»
Книга лежит в `ai-agent-book/` (русский перевод, Bojie Li). Из неё взяты решения по устройству агента:

| Решение | Глава |
|---|---|
| Без фреймворков; каждое число расчёта показывает, из чего получено | 1, «Основные принципы построения эффективного агента» |
| Режим расчёта описан порядком шагов, а не списком правил | 2, «Процессный подход против нагромождения правил» |
| Способы счёта и единицы заданы явно; что решает человек, названо прямо | 2, «Детализация бизнес-правил» |
| Один разобранный пример вместо длинных описаний формата | 2, «Few-shot-примеры» |
| Навык состоит из роли, главных принципов, запретов, справочных файлов и программы | 2, «Как написать пригодный к использованию Skill» |
| Знания лежат обычными файлами со ссылками между ними и читаются по надобности | 3, «Файловая парадигма» |
| Считает программа, а не модель | 4, «Формы представления возможностей» |
| Свой набор проверочных случаев и повторные прогоны одного случая | 7, «Оценка AI-агента» |
| Проверяет другая модель, а не та, что писала | 10, «Одноранговое взаимодействие» |

## Как обновлять
`знания/` собираются из `veselkov/cards/` и `Методика оператора (черновик).md`. После правок методики или карточек файлы в `знания/` нужно пересобрать, иначе агент работает по старой версии. Версия указана в шапке `знания/методика.md`.
Для плагина ChatGPT после обновления знаний выполните `python3 оператор-агент/собрать_плагин.py` из родительской папки: сборщик обновит копию в `chatgpt-plugin/` и версию плагина.
